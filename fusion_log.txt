MiniCPM-SALA Kernel Fusion Log
Model: openbmb/MiniCPM-SALA (9.5B params, 32 layers, hidden=4096)
Architecture: 8 minicpm4 (sparse attn) + 24 lightning-attn (SimpleGLA) layers
================================================================================

FUNDAMENTAL PRINCIPLE: ZERO ACCURACY DEGRADATION
  All fusions MUST preserve or improve numerical precision. No fusion may
  introduce accuracy loss compared to the original computation path.
  This is a hard constraint — performance gains are worthless if they
  degrade model output quality.

ACCURACY ANALYSIS:
  Kernels #1-6: All compute in float32 accumulation, bf16 I/O.
    Numerically identical to the unfused operation sequences.
  Kernel #7 (fused_qknorm_rope): STRICTLY MORE PRECISE than original.
    Original: qknorm writes bf16 → reads bf16 → casts float32 → RoPE → bf16
    Fused:    qknorm in float32 → RoPE in float32 (no intermediate bf16 truncation) → bf16
    The intermediate bf16 truncation between RMSNorm and RoPE is eliminated.
  Kernel #8 (fused_gemm_sigmoid_gate): STRICTLY MORE PRECISE than original.
    Original: cuBLAS GEMM → writes bf16 → reads bf16 → float32 → sigmoid → bf16
    Fused:    Triton GEMM accumulator (float32) → sigmoid (float32) → bf16
    The GEMM output bf16 truncation before sigmoid is eliminated.
  Note: Triton GEMM may produce bit-level differences vs cuBLAS due to
    different floating-point reduction order (non-associativity). This is
    NOT accuracy degradation — both are valid float32 computations.

7  fused_qknorm_rope              q_norm + k_norm + RoPE rotation       24        120

                                  k.float() + rotary_emb + q.bf16()
                                  + k.bf16() = 6 kernels -> 1 kernel
                                  (lightning layers only)
8  fused_gemm_sigmoid_gate        Triton GEMM + sigmoid + multiply       8          8
                                  Replaces: o_gate GEMM + sigmoid_gate
                                  = 2 kernels -> 1 kernel
                                  Eliminates intermediate tensor
                                  (minicpm4 layers, BF16 weights only)
                                                              SUBTOTAL:          ~315

Profiling code removal (import time, synchronize, perf_counter):        ~5 syncs

Cross-layer fusion detail:
  BEFORE: layer N ends with   residual + mlp_out * scale  (2 ops)
          layer N+1 starts    residual = h; h = layernorm(h) (1 op)
  AFTER:  layer N returns     (mlp_out, residual)
          layer N+1 calls     fused_scale_residual_rmsnorm(mlp_out, residual, ...)
  Saves 32 kernel launches (one per layer boundary).

NOT DONE (requires weeks of CUDA engineering)
================================================================================

- Persistent decode kernel (single kernel for all 32 layers' GEMMs)
  Would give 10-20% at bs=1 but requires ~10K lines of CUDA.
  NVIDIA TensorRT-LLM has this; too complex for a kernel fusion patch.

- CUTLASS GEMM epilogue fusion for lightning z_proj + rmsnorm + sigmoid
  The minicpm4 o_gate path is now fused (#8 above) via Triton GEMM.
  Lightning layers' z_proj would also benefit, but fusing rmsnorm variance
  reduction with the GEMM tiling requires CUTLASS 3.x cooperative epilogues.

- Self-speculative decoding using early lightning layers as draft model
  Would give 2-3x decode throughput at bs=1 but requires training
  an early-exit LM head + modified serving loop.
